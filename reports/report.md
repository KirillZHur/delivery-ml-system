# Итоговый технический отчёт — Delivery ML System

**Источник:** машинные результаты полного конвейера, профиль `full`. **Тесты:** 136 passed. **Контрольный SHA-256 исходников:** `abfbd59c28713659f2ac7bc11f8be44bda6b086f625296525972f391684513c8`.

## 1. Контракт решения и ограничения
Сервис оценивает число часов доставки в момент оформления заказа. Входы: расстояние (0–1000 км), известная к моменту решения загрузка склада и прогноз дождя. Выход: оценка, 90%-й интервал, идентификатор версии и флаг деградации. Метрики: MAE (главная), недооценка и покрытие интервала; целевой p95 полного HTTP-ответа ≤100 мс на 20 запросах/с. Простое решение — медиана тренировочной выборки.
Формула синтетического срока: `clip(12 + 0.04·distance_km + 18·warehouse_load + 6·rain_forecast + N(0,3), 1, 168)`. Преобразования и версия модели загружаются единым проверяемым комплектом.

## 3. Лестница моделей и протокол выбора
Препроцессинг обучается только на train. Выбор модели производится по зрелым февральским меткам; мартовский test открыт однократно.

| Модель | MAE train, ч | MAE validation, ч |
|---|---:|---:|
| Константная медиана | 10.714 | 11.065 |
| StandardScaler + Ridge | 2.434 | 2.398 |
| HistGradientBoostingRegressor | 2.347 | 2.459 |
Выбрана **linear**, потому что дала минимальную валидационную MAE. Медиана не учитывает признаки, линейная модель выявляет почти линейную зависимость, бустинг здесь не улучшает обобщение.

## 5. Сервис, резервный путь и эксплуатационный контракт
`src/service.py` реализует `/predict`, `/health/live`, `/health/ready`, `/metrics`, проверяет типы и диапазоны. `src/feature_store.py` разрешает только своевременно поступившие события и применяет 20-мс тайм-аут. Нет признака, истёк срок годности или недоступен источник — явный резервный расчёт с `degraded=true` и кодом причины. На неизвестные поля/обязательные значения API отвечает ошибкой валидации; порядок признаков берётся из манифеста, а не из порядка ключей JSON. Проверяются недопустимые значения бинарного признака и ограничения числовых полей; реальное хранилище и очередь здесь не развёрнуты.
Паритет HTTP-ответа с офлайн-эталоном: максимальное расхождение **1.42e-14 ч**. Сервис загружает модель один раз и проверяет SHA-256 и версию калибровки.

## 6. HTTP-нагрузка и ускорение
Машина замера: `macOS-26.7.3-arm64-arm-64bit-Mach-O` (3.13.5). Отдельные одно-процессные Uvicorn-серверы, одинаковые payload и планировщик, прогрев, persistent connections, измерение от начала HTTP POST до разбора ответа, включая PIT, JSON и audit. Синтетический локальный поток не эквивалентен внешней сети. Серверный handler измерен отдельно.

| Режим | Нагрузка | Измеренных запросов | Медиана HTTP, мс | p95 HTTP, мс | Выполнено, rps | Ошибки |

| baseline | 20 | 240 | 6.477 | 7.640 | 20.1 | 0 |

| baseline | 40 | 80 | 6.617 | 8.015 | 40.3 | 0 |

Оптимизация `StandardScaler+Ridge → pre-computed linear weights`: изменение p95 при 20 rps **7.640 → 5.915 мс** (22.6%). Размер файла модели **753 байт**; модель и качество не меняются. Для иных машин показатели могут быть другими; сырые значения в `reports/latency_raw.csv`.

## 7. Shadow / canary / rollback
Воспроизведён sticky user_id assignment, теневой режим, шаги 5%, 25%, 100%, удержание двух здоровых окон, недостаточность данных и откат. Манифесты версий и артефакты проходят проверку совместимости. Правило технических ошибок: >1% в двух последовательных окнах по ≥1000 запросов кандидата; независимо контролируются p95 ≤100 мс и доля degraded ≤5%.

| Сценарий | Решение | Окон | Итоговая доля v2 |
|---|---|---:|---:|
| healthy | promoted | 7 | 100% |
| shared_outage | promoted | 9 | 100% |
| candidate_latency | rolled_back | 4 | 0% |
| candidate_errors | rolled_back | 5 | 0% |
| candidate_degraded | rolled_back | 4 | 0% |
Малое окно: **100** запросов, кандидат получил **9**, решение **hold**. Подтверждение восстановления v1 через HTTP: **verified**. Уже принятые v2-запросы завершаются со своей фактической версией после переключения. Поломка общего источника требует восстановления источника, а не бессмысленной смены модели.
**Граница доказательств:** p95/ошибки в контроллере заданы синтетическим сценарием. Реальные измерения HTTP приведены выше, а не подменяют искусственные инциденты.

## 9. Локальное переобучение и проверка допуска
Политика: ежемесячно после закрытия семидневных когорт и дополнительного часа поступления меток; может запускаться при подтверждённом дрейфе или ухудшении зрелой MAE. Ответственный в реальной системе — владелец ML-модели / дежурный ML-инженер.
На снимке 2026-05-10T00:00:00Z — обучено на **18684** зрелых заказах (новых **2684**), калибровка **662**, отдельный gate **654**. Мартовские метки test не входят в этот цикл.
Действующая модель MAE gate **2.32614 ч**, кандидат **2.32599 ч**, покрытие **89.14%**, решение **promoted**; искусственно испорченная версия MAE **8.773 ч**, решение **rejected**. После отказа активна **delivery-2026.2-linear**.
Сервис кандидата проверен через FastAPI TestClient (не внешняя нагрузка); для реального выпуска требуется проверка в том же целевом окружении и подтверждение владельцем. Предыдущий комплект с проверяемой контрольной суммой SHA-256 остаётся доступным для rollback, работающий процесс должен быть перезапущен.

## 10. Ограничения и дальнейшая проверка
Данные независимые и синтетические; нет сезонности, логистических пробок, пространственной автокорреляции, настоящих изменений спроса или стохастических задержек меток. Условная симуляция ошибок не демонстрирует устойчивость к реальным отказам инфраструктуры. Результаты p95 получены через localhost в одном процессе; нет нескольких реплик, реальных сетевых задержек и реального 24/7 SLO. Интервал не имеет строгой distribution-free гарантии. Пользу для покупателей необходимо оценить отдельным A/B-тестом с бизнес-метриками обещанного срока и жалоб. Следующий опыт: внешний HTTP-нагрузочный стенд плюс A/B-тест на реальных доставках с независимой калибровочной выборкой.
